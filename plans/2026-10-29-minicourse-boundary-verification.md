## Изменения и найденные проблемы

Воспроизводимых дефектов продуктового кода не обнаружено. Страница, дизайн,
ядро/контроллер калькулятора, регистрация и серверная основа не изменялись.

Устранён пробел проверок: прежний `verify` использовал только dev, а module-failure
test блокировал только URL TypeScript-исходника. Добавлены отдельная production
конфигурация, команда и включение её в `verify`; исправлены два жёстко заданных
dev-адреса no-JS tests и усилен matcher сбоя модуля. Добавлено 20 проверок границ
с повторным использованием существующего набора, без новых зависимостей.

Во время разработки наблюдатель submit дал ложное срабатывание: capture-listener
проверял `defaultPrevented` до целевого обработчика калькулятора. Наблюдение
перенесено в bubble-фазу после обработчика. Ошибка TypeScript в обёртке перегруженного
XHR.open исправлена через Proxy с сохранением сигнатур. Это ошибки новых проверок,
не дефекты приложения и не отдельная история исправлений для портфолио.
Первый полный verify дополнительно выявил слишком широкую инъекцию отказа:
блокировка всех Storage.getItem создавала необработанные `Blocked` в dev-контексте.
Установленный Astro dev-toolbar читает localStorage в
`runtime/client/dev-toolbar/settings.js`; широкая инъекция затрагивала и его.
Отказ ограничен sessionStorage и ключом демо; guard по-прежнему запрещает любые
необработанные ошибки. Целевые read/write tests после уточнения прошли в dev.

`node_modules/.astro/sessions`; runtime Astro создаёт объект сессии лениво при
обращении к нему. Прослежены index → компоненты → локальный контроллер и оба

записи демоданных нет. Перед browser tests каталог файлов сессий пуст; после
целевых production tests он также пуст, данных демо/калькулятора в логах нет.

`dataInLogs=false`; stdout — 67 байт, stderr — 164 байта (предупреждение Node
о FORCE_COLOR/NO_COLOR). Это не ошибка страницы или проверки типов.
Проверка сравнивает имена/размер/mtime, не читает значения сессий и ничего не удаляет.
Обычные HTML/JS/CSS/шрифты/изображения и image transformation не считаются отправкой
заявки; отсутствие прикладного хранилища подтверждается также анализом точек входа.

Поведение сессий сверено с [официальной документацией Astro](https://docs.astro.build/en/guides/sessions/)
